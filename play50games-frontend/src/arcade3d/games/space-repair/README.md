# Space Repair Mission

Owner: Codex (reassigned by the user, 2026-10-09). Slug: `space-repair`. Skill game 16, wave 3, complexity 3. G0 design for P-14, not an implementation. Spec: `docs/arcade-expansion/04-game-specs-skill.md` §16; catalog: 05 §E.4. Units: metres, played seconds, radians; x east, z south, y up. Core verified against local `origin/main` **bd65ac3**, without fetching. Every departure is labelled below.

## Concept

Float around a toy station, brake beside a sparking module and tap a large timing ring to mend it. Keep power above zero for **120 s**. Eight numbered modules, a silver astronaut, blue solar wings and Earth below make the route readable; inertia between repairs and a satisfying wrench reach give it its identity. Accent `#818cf8`.

## Controls

`meta.ts` controls: `scheme: "joystick"`; `keyboard: "WASD / arrows to thrust; release to brake; tap E, Enter or Space in the repair arc"`; `touch: "Joystick to thrust; release to brake; tap Repair in the repair arc"`. Definition: `touchControls: ["joystick", "action"]`, `touchLabels: { action: "Repair" }`.

- `moveX/moveY` → `inputToWorld(..., view.yaw, scratch)`; clamp vector magnitude to 1, dead zone 0.12. Repair reads `actionPressed || jumpPressed` once per rendered playing frame, never once per substep. E/Enter/Repair map to Action, Space to Jump; simultaneous edges are one attempt. Held input and OS repeat do not repeat repair. No mouse aim, canvas taps, swipes, drag or extra touch button.
- Esc/P and hidden-tab pause are shell-owned. Coarse-pointer mode is sampled once at run start and fixed until Retry; it changes arc width only. Both devices use neutral braking and the same leaderboard.
- Changed from spec: arrows/Enter follow existing core bindings; desktop gets the same neutral brake as touch because counter-thrust alone makes stopping in a small service disc unnecessarily difficult. The exact help strings disclose braking.

## Rules

Pure seeded `rules.ts`; literal groups `STATION`, `SUIT`, `BREAKS`, `REPAIR`, `DEBRIS`, `CELL`, `SCORE`, `CLOCK`. No Rapier, mesh-derived collisions or wall-clock time. One `useRunFrame`; core `substep` consumes all played dt in steps ≤1/120 s, with splits at scheduled events, lock expiry, cell eligibility/expiry, power zero and 120 s. Cache the callback and scratch. Frame-sampled input is not claimed identical under different input sampling times.

- **Station:** flight square x/z ±10; centre clamps to ±9.55 for astronaut r0.45. Module i=0..7 is at `(4.2*sin(i*pi/4), 4.2*cos(i*pi/4))`; its service disc is at the same angle, radius 6, disc r0.6. Module visual diameter 1.3, height 1.2. Footprints: each module is a circumscribed regular 12-gon of inradius 0.65; hub a regular 16-gon of inradius 1.2 at origin; solar wings AABBs x[8.1,9.3] and [-9.3,-8.1], z[-1,1]. These fixed closed segment lists use core circle/segment contacts. Struts and docking-port trim are cosmetic, below the flight plane; no invisible connector walls. Minimum service-disc separation from its own collider is 1.8−0.6−0.65/cos(pi/12)−0.45 >0.077.
- **Astronaut:** start at service disc 0, velocity zero, facing the hub. XZ thrust 6 m/s²; speed cap 7 after thrust AND contacts/knockback. Neutral means input magnitude ≤0.12; reduce speed by `min(speed,3*dt)` without reversing. Use trapezoidal displacement from pre/post-force velocity, then contact resolution. Facing eases at 8/s towards travel above speed 0.2, towards the module while docked; yaw has no rule effect. Visual soles float at y0.25; no walking gait on empty space.
- **Contacts:** `circleSegmentXZ` + `resolveCircleSegmentXZ(...,0.5,0)` for fixed footprints, stable module/edge order; at most 4 resolution passes then retain the last legal position and remove inward velocity if still overlapping. Also reject a corrected position whose displacement exceeds7*dt: retain the last legal position/remove inward velocity, never gain travel from push-out. Boundary clamp reflects only outward velocity at restitution 0.5. Contact entry starts 0.5 s cosmetic wobble and cancels docking; re-arm entry after separation≥0.05, shared wobble cooldown0.5 s prevents corner strobing. No power/score penalty. Slice travel7/120<0.059 is below body radius0.45, so a resolved body cannot cross a segment's centreline between tests; shortest solid width≥1.2. Tests include corners/interior recovery and bounded corrected displacement, not merely endpoint overlap.
- **Break tickets:** exactly 32 candidate events: 6,12,18,24,30,36; 40,44,...,76; 80,82.5,...,117.5. RNG state is `{s:(seed>>>0)||1}`; first `rngNext` chooses direction (value<0.5:−1, otherwise+1), next8 samples set module arc offsets in id order, next4 set debris phases in slot order; no later RNG draws. Ticket k targets module `(direction*k mod 8 +8) mod 8`. First target is always 0, making the opening teachable. If that module is already broken, consume/skip the ticket: no queued duplicate, reset, extra drain or future award. Otherwise create one broken generation with hits=0 and perfect=true. Repairs cannot create tickets; maximum four paid generations per module.
- **Power:** starts 100; derivative = minus the number of currently broken modules (1/s each), including travel, docking and miss locks. Integrate exactly between event times; clamp only after a +25 cell, to [0,100]. No passive regeneration, no direct collision damage. Zero is absorbing. Below 25: steady warning text/bar/vignette and alarm on downward crossing; re-arm above 30. Each module shows its number, broken icon and completed/required hit pips. HUD: Power floor(P)%, Repairs n, Remaining ceil(120−t)s; shell Played remains shell-owned.
- **Docking:** eligible only inside a BROKEN module's service disc, speed ≤1, neutral input and wobble expired; choose nearest disc, ties lower module id. Latch at the current legal position and set velocity zero (no position snap/free travel). While neutral and eligible, hold there; movement >0.12 unlatches immediately. Leaving retains that generation's hit count/perfect flag, but resets needle age to zero. No repair while moving, wobbling, outside the disc or at a healthy module; such presses do nothing and grant no points.
- **Required hits:** modules [0..7] require **[1,1,2,1,1,2,1,3]**, fixed for the whole run (mean 1.5). Their cap stripes/pips distinguish size without changing footprint/reach. Repair parameters snapshot when a ticket actually breaks the module: stage at t<40 / 40≤t<80 / t≥80; periods **1.2/1.0/0.8 s**; fine-pointer widths **60/45/35°**, coarse **90/75/60°**. Seeded arc centre for module i is `0.5 + 0.05*(2*rngNext−1)` turns, frozen across its generations; zones never wrap (bounds inside 0.325..0.675). Use `needlePosition(age,period,"loop")`, `judgeTiming(pos,zone,1/3)`; arc endpoints and perfect-third endpoints are inclusive.
- **Timing attempts:** entry, each successful hit and each completed miss lock reset needle age to zero. An eligible new press is graded once against that frame's rule needle; good/perfect adds one hit, perfect flag ANDs with the grade. A miss clears perfect, retains hits, freezes needle at zero for **0.5 s**; presses during lock are discarded, not queued. After a successful hit the next hit must wait for the reset needle to reach the arc again; two keys cannot finish multiple pips. Reaching required hits repairs exactly once, clears drain immediately and emits one score event. No randomness or extra survival points on a miss. Changed from spec: explicit reset/lock/latch/progress semantics close the hold/spam and repeated-hit-in-one-arc loopholes.
- **Cells:** successful-repair milestones 4,12,20 each spawn one `SHARED_ASSETS.battery`, no other source. Position = that module's service centre +1.3 m along increasing-index tangent, y1.1. After 0.35 s, automatically collect within XZ distance ≤2.0 for +25 power (capped100), zero score; expire after 8 s if missed. A docked player is ≤1.9 away, so waiting briefly guarantees pickup; moving away can miss it. Three single-use slots, id-order collection, no respawn. Battery long axis is camera-up, visible fitted length 1.0 m; bob ≤0.04. Changed from spec: the catalog's otherwise unspecified P2 cells become three finite milestone recharges, giving late human repair queues a power margin without farming.
- **Debris:** one closed 32-point `createPath` polygon, vertices on r7.6, y0.95; phase = `j/4 + seeded offset in [-0.025,0.025]` turns for slot j=0..3. Activate 2/3/4 slots at 0/40/80 s, speeds 1.0/1.2/1.4 m/s by current stage; `advance` all four paths from time zero so later activations do not teleport existing pieces. Each is drawn diameter0.5, collision circle r0.25. Contact with astronaut uses `circlesOverlapXZ`; apply outward normal impulse2 m/s, cancel latch, wobble0.5, global debris cooldown1 s (coincident centres: outward station radial normal, +z at origin). Speed cap still7. No drain or score from debris; it need not collide with station props. The polygon stays outside every service disc/player clearance and inside solar-wing clearance, so repairs and the inner adjacent route are safe; it punishes overshoot rather than unavoidable camping damage.
- **Frame/event order:** advance continuous movement/timing/drain to the next boundary; power zero ends before anything can revive it. Then break tickets, contacts/unlatch, frame-end repair edge (if its sample time is not after120), milestone spawns, eligible cell collections, final survival award/win. New breaks start draining only AFTER their instant; repairs/collections cannot undo earlier drain. A frame straddling120 integrates only to120 and discards later input/remainder. At exact120, loss has priority; a legal repair/collection at that same instant precedes bonus/win. Pause/over advance nothing; Retry resets schedule/RNG/slots/locks.
- Changed from spec: simultaneous broken modules arise from backlog; no extra simultaneous ticket burst beyond the 6→4→2.5 s cadence, because travel plus multi-hit repairs already raises late load. The 32-ticket schedule, spatial order and safe inner route replace unspecified arbitrary breakdown placement with a human-paced finite challenge.
- **Human budget (estimates, not measurements):** adjacent service centres are 4.592 m apart. A conservative centre-to-centre accelerate/neutral-brake trip from rest with a=6,b=3 needs v_peak=sqrt(4*4.592)=4.286<7 and 2.143 s; allow 0.5 s for reaction/settling →2.65 s. At the latest stage an average 1.5-hit repair takes about 0.6–0.8 s including reaction; allow one miss per four modules (+~0.2 s/module). Thus about 3.5–3.7 s/service, with early 6/4 s intervals building reserve and a late backlog of ~4–5, rather than requiring 2.5 s human responses. Target 26–28 repairs, total broken-time drain110–135, effective cell recharge45–65 after caps, final power10–55. First-60-s novice target ≥40 power with ≤1 miss/module; build must record real keyboard/two-thumb witnesses and revise openly if these estimates fail. No ideal-bot timing substitutes for that gate.

## Scoring

`runScore = 100*repairs + 50*perfectRepairs + (won ? 2*floor(powerAt120) : 0)`. Perfect means EVERY required hit was perfect and there was no miss during that broken generation. Live `addScore(100|150)` once per completed generation; no awards for individual hits, cells, movement, idle time, bounces or power replenishment. Final `setScore(runScore)` reconciles once before `end`, not another additive award; no `finalScore` override. Loss retains repairs and receives no power bonus. At most **32*150+200=5000**; this is a conservative ceiling, not a claimed attainable oracle score. Popups +100/+150 perfect; HUD and result expose the power bonus.

## Run end

- Rules own a fixed **120 s survival clock**, `durationMs` OMITTED: first P≤0 calls `end("lose")`; otherwise at t120 reconcile repairs/power bonus and call `end("win")` in the same callback. Completing/repairing all currently broken modules does not end early. No gameplay `"timeup"` reason.
- Changed from spec/Common clocks exception: survival uses explicit `"win"` instead of shell `"timeup"`, because timeup displays a loss and suppresses the game's last callback/bonus. Shell still owns phases, pause, result/submission, Retry and Exit; game shows Remaining itself and never calls storage/API.
- `resultDelayMs:1200`; win has mint repair flash/confetti/cheer, loss darkens panels and the astronaut slumps. Motion/awards freeze; visual result animation uses `useGameTime().now` only.
