## Concept

A brave vinyl-toy pigeon hops across traffic in seven columns. Read approaching cars/taxis/vans, wait on grass and commit to short crossings. Each far-side arrival starts another faster/denser level. V1 uses **road and grass only**: logs/water would introduce drifting support and a second failure model without improving the central traffic-reading challenge.

Survival continues until a vehicle hit, with a defined **30-minute run cap** to respect the server duration window. There is no short round timer, life system, invulnerability pickup or automatic forward movement. At the cap GameShell ends with `"timeup"`; a hit ends with `end("lose")`. Completing a level does not end the run.

## Controls

Metadata uses scheme `"hop"`, "Arrows / WASD: one hop per press", "Swipe in any direction; tap hops forward". `touchControls: ["swipe", "tap"]` needs no joystick/action buttons.

- **Hops come from core `input.pressed` only.** `pressed.up/down/left/right` is set for every new keydown of an arrow or WASD key (auto-repeat does not count) and for every swipe. It is latched and published on the next frame, so no press is lost, however short: a keydown and keyup inside one frame still hops once. Up moves forward (-z), down backward, left/right one column. Holding a key does **not** repeat; the next hop needs a new keydown. `moveX`/`moveY` are not read.
- **Swipes are already in `pressed`.** A swipe sets `swipe` and `pressed[direction]` on the same frame, so the game never reads `input.swipe`: a `swipe` branch would hop and then queue a second hop for the same gesture. Core fires a swipe mid-gesture, at 30 px of travel within 700 ms, so the hop starts while the finger is still moving.
- **A tap is one forward hop**, from `input.tap`. Core has no tap-down event: a tap is reported on release (at most 12 px and 350 ms, no travel), and a gesture that swiped is never a tap. The tap position is ignored; tiles are not individual tap targets. Touch events originate on the canvas, not shell buttons/overlays.
- **One hop request per frame.** If a frame carries several (two keys within one frame, a key plus a tap), take the first of up, down, left, right, then tap (as up); the rest are dropped, not queued. No diagonals. Two presses of one direction inside one frame are one press (core).
- Read only `useInput().current` inside `useRunFrame`. At rest validate from the current cell, then start one valid hop. During a hop, validate a request **from that hop's destination row/column**, not its origin or interpolated position; store at most **one queued direction**. The first valid request wins; later ones are discarded until it is consumed. An invalid request is dropped immediately and **does not take the queue slot**, so a later valid request can still queue. A press is used once. No wall-clock input buffer or browser key-repeat handlers.
- Reject target columns outside 0..6 or rows outside the current level's 0..20. Examples: while hopping column 5→6, a right press targets 7 and is dropped; while hopping 0→1, a left press targets 0 and is valid. On landing revalidate the queued target from the landed cell before consuming it. Collision/end/level transition clears the queue; do not chain after death or into a new level. Invalid moves earn nothing.
- Requests during the protected preview are dropped (no hop, no queue); the first hop needs a press after the preview ends, and held keys never launch.
- Esc/P, hidden tab and blur pause through GameShell. Pause stops traffic and the mid-hop position too. Phase changes clear pending one-frame events (core `clearEvents`), so a press made while paused or counting down never hops on resume; blur releases held keys.

## Rules

World units are metres, +y up; forward advances a row along **-z**, cars move along ±x. Seven column centres are x = -4.8, -3.2, -1.6, 0, 1.6, 3.2, 4.8.

- Each level has **20 new rows** beyond its start: row 0 is safe; grass rows are **0, 3, 6, 9, 12, 15, 18, 20**. Other rows are roads: six two-road groups and the final single road. Row 20 is the far-side grass. Consecutive grass boundaries give somewhere safe to wait for every road group.
- Each accepted hop moves exactly one cell in **550 ms simulation time**, with linear ground x/z interpolation and a visual 0.25 m arc. Collision uses the ground position throughout: jumping is not invulnerability. No mid-hop steering, cancellation or shorter reduced-motion hop. Consume remaining dt across hop boundaries without double-counting; every new hop requires its own 550 ms before landing/points.
- **Collisions use core `sweptAabbXZ`.** `step` splits each frame's dt into substeps at hop boundaries (takeoff, landing, a queued hop's start), so the pigeon's ground motion and every vehicle's motion are linear inside a substep. For each active vehicle in the pigeon's origin and destination rows, call `sweptAabbXZ(pigeonBox, delta, vehicleBox, hit)` with both boxes where they are at the substep's start and the relative motion `delta = pigeonDelta - vehicleDelta` (preallocated boxes, delta and `SweepHit`). The earliest time of impact over all of them is the contact: `step` advances everything to that instant and stops, so pigeon and vehicles stay at the touching positions, then reports the hit (`end("lose")`). Touching counts, a box already touching at the substep's start gives 0, and nothing tunnels between frame endpoints. A contact at the same instant as a landing wins over the landing's points and level completion. A vehicle born or removed inside a substep is swept only over its live part; births and deaths lie under the side cover, at least 0.92 m from any pigeon box, more than a frame's 0.4 m of travel.
- Start each run with a **3050 ms protected grass preview**, counted as playing time: no hop, queue or collision before it expires. Traffic/visual time advances normally; show "Watch the gaps". This exceeds the 3000 ms server minimum by 50 ms of conservative slack; all preview time is counted. The shell's 3-2-1 countdown is separate and not submitted time.
- A new furthest row reached **on a surviving landing** pays 10; backtracking/lateral hops or revisiting rows do not. A far-side landing pays that row's 10 plus **100 level bonus** once, then increments Level. The shared boundary grass is the next level's row 0 and pays no extra points. Block retreat into completed levels to prevent bonus farming.
- Levels occupy consecutive world rows (no teleport). Fill preview lanes before they enter the **full visible-ground horizon computed in `camera.ts`**, using the same absolute simulation time before/after activation; entering a level cannot restart traffic or reveal an unfilled lane. Reset only its local furthest-row mark, not the run clock/total progress. The fixed ring below keeps previous/current/next partial levels visible as needed.
- Seed generation is in Scene on each mount: lazy `useState(() => createRun(randomSeed()))`, using core `randomSeed()` outside rules. Rules take that uint32 parameter and draw only with **core `rngNext(state)`** (`state = { s: levelSeed }`, kept in the run's preallocated fill scratch; the same sequence as core `createRng(levelSeed)`, without a closure per row). No local PRNG copy, no `Math.random` or global random source inside rules. Derive each level's stream from `(seed ^ Math.imul(level, 0x9e3779b9)) >>> 0`, with a stable generation order. Integer vehicle-kind weights car:taxi:van = 4:2:1; phases/start offsets use integer milliseconds. Seed plus the same dt/input timeline reproduces traffic and collisions.

### Constants and traffic fairness

Let difficulty tier `d = min(level, 10)`, with level starting at 1. Levels 1–10 get faster/tighter; later levels retain the tested maximum rather than becoming impossible.

| Constant | Value / rule |
|---|---|
| Columns / column pitch | 7 / 1.60 m; playable x edges ±5.60 |
| Rows per level / lane width | 20 forward rows / 1.80 m along z; one level spans 36 m |
| Hop duration / visual height | **0.55 s** / 0.25 m; all directions, queued or not |
| Initial protected start | **3.05 s**; only once per run |
| Pigeon model / collision | Nominal **1.25 m tall**, folded-wing visual width **0.56 m ±5%**; ground AABB **0.56 x × 0.50 z** (half extents 0.28 / 0.25); unchanged collision rules |
| Car hit box / speed | **2.80 x × 1.15 z**; `min(8, 3.0 + 0.6*(d-1))` m/s |
| Taxi hit box / speed | **3.10 x × 1.20 z**; `min(8, 3.4 + 0.6*(d-1))` m/s |
| Van hit box / speed | **3.80 x × 1.30 z**; `min(8, 2.6 + 0.6*(d-1))` m/s |
| Bumper gap inside a pack | `g = 3.0 - 0.2*(d-1)` m, **3.0 down to 1.2** |
| Pack size per road/cycle | `1 + floor((d-1)/3)`, **1 up to 4** |
| Spawn headway | At least `(3.8 + g) / laneSpeed` seconds between pack members; no overlap |
| Traffic cycle / clear window | **12 s**, with the complete play width empty in phases **[9, 12)** of each road group's cycle |
| Spawn/despawn outside edge | Vehicle centre at x = ±`(5.6 + length/2 + 0.4)`, travelling across; never teleport through play |
| Side occluders | Opaque roofed building blocks at **\|x\| ≥6.0**, height 1.8 m, through the full projected view edges; vehicles fit inside their 1.5 m height limit |
| Fixed pools | **40 lane slots** in one absolute-row ring, **4 vehicle slots per lane** (160 total); never resize or replace them |
| Gameplay cap | `definition.durationMs = 1800000`; no extra game timer |

Each two-road group shares one seeded cycle phase, while directions alternate. A lane has one seeded vehicle kind and constant tier speed. A pack's starting offset is drawn in integer ms from 0 through `floor(1000 * min(2, 9 - travelTime - (packSize-1)*headway))`, where `travelTime = 2*(5.6 + length/2 + 0.4)/speed`. This upper bound must be nonnegative and every member's trailing edge must be off the playable width by phase 9. No spawning in the clear window. Apply the same rule to the final single road.

**There is always a passable gap:** during the shared 3 s clear window, both roads are empty across **all seven columns**. From preceding grass, three forward hops reach the next grass in 1.65 s; even allowing a 0.35 s reaction plus three 0.05 s frame/input delays, this is **2.15 s**, leaving **0.85 s margin**. The final single-road crossing needs only two hops. Safe grass can be waited on indefinitely until this window repeats; future levels use the same guarantee. Seed can change appearance, direction and timing, never remove the window.

The generator validates pack spacing/exit deadlines and the shared-window invariant; a deterministic one-car-per-cycle fallback with start offset 0 preserves them if validation fails. Do not silently emit a blocked layout. Tests must additionally find a time-expanded path through every level and check swept collision along its hops. Fairness guarantees an available route, not safety for a player who hops outside the gap or idles in the road.

### Hidden traffic boundaries and fixed pools

The **12 s cycle, spawn positions, travel time, headways and [9,12) clear window stay unchanged**. At a birth/death centre `|x| = 6.0 + length/2`, even the nearest bumper is at `|x| = 6.0`; the entire vehicle is inside a side occluder. Use solid opaque roofed building blocks with closed inner faces covering |x| ≥6.0, not glass or open portals that expose the interior. Their roofs enclose vehicle meshes up to 1.5 m; blocks are 1.8 m tall. Cover the boundary seam with depth bias/clipping at |x| ≥6.0. A vehicle gradually emerges past the inner face and retreats behind it before its slot becomes inactive. No visible alpha/scale pop, wheel/light trail outside the cover or modulo teleport across the street. Occluders are scenery, not new gameplay colliders.

`camera.ts` determines cover extent from the core-fitted camera's full visible-ground/height envelope, **not the active-box edges**. Extend each side block to `max(6.0, maxAbsVisibleGroundX + 1.9 + 0.4)` and along the entire generated row horizon plus each row's 0.9 m half-width. Recompute before a resized view is rendered. The settled reference fits (table below) need outer x cover **±12.073 m** at 375 × 812 and **±21.614 m** at 1280 × 800; wider canvases need more (±27.398 m at 1366 × 657), so the cover is always computed from the live fit, never a constant. Round cover dimensions outwards. Use fixed primitive block meshes with changing dimensions; no generated asset is needed.

- Allocate exactly **40 lane records and 160 vehicle records once on Scene mount** (capacity equal to two levels × 20 rows, not two separately allocated level arrays). Index lane slots by `absoluteRow % 40`; tag each with its absolute row and seeded level. A visible window (28 guarded rows at 375 × 812, 31 on a 344 × 882 phone) can straddle three partial levels without storing three whole levels. Shared row 20/next row 0 is one absolute grass row, not two descriptors.
- Generator, validator and deterministic fallback **fill existing slots in place**, including each lane's four vehicle records; unused records are inactive. Grass has no active vehicles. Scalar loop indices, preallocated scratch/`rngNext` state and fixed event counters replace per-frame arrays, closures, maps, filters, object literals or returned descriptor lists. `step` and any fill/validation/fallback it calls must allocate none of these.
- Draw with core **`rngNext`** on the fill scratch's `{ s }` state: reset it with `state.s = levelSeed` and replay the level's fixed row/group draw order; group members reproduce the same shared phase regardless of fill order. No game-local mulberry32 and no new RNG closure per row: core already tests that `rngNext` gives `createRng`'s sequence (`math.test.ts`). No new scratch level array is required, and later visibility/resize never changes a descriptor's identity or random choices.
- The cached numeric horizon from `camera.ts` is supplied to simulation/rules. Fill entering guard rows before stepping/rendering; derive all four vehicle positions from absolute `run.timeMs`, so a newly filled preview never starts its own clock. The one-row guard exceeds the camera's maximum per-frame advance `1.8/0.55 * 0.05 = 0.163637 m`.
- Reuse a slot only when its old row's complete slab/vehicle height envelope is outside the visible horizon and it cannot contain the pigeon or a hop destination. A vehicle's ordinary cycle birth/death additionally requires complete occluder cover. Never reuse a visible lane because it left the smaller active box. On a paused resize, fill the new horizon at frozen time before applying the new projection; no empty-frame flash or new traffic phase.
- The view gate (below) pauses a view whose guarded horizon needs more than 40 rows; never grow the ring or evict visible lanes. Geometry/material/instance identities remain fixed across hundreds of levels, backtracking and permitted refits. Validate that the 40/160 bounds hold even when the fallback is used.

### Simulation timing and frame order

All hop progress, start hold, vehicle displacement/spawns and gap phases advance **only by `useRunFrame` → `step(state, dtMs, input)`** at the core's default simulation priority **-0.5**. The hook dt is seconds: exactly **`frameMs / 1000`**, at most 0.05 s; Scene passes `dt * 1000` to rules. Every playable frame is counted, including the residual frame when countdown ends. The integer `run.timeMs` carries fractional milliseconds and never forces a 1 ms step. Pool preparation before RunClock pauses an invalid resized view before any playing dt is counted; it never steps gameplay. A second preparation after CameraRig covers the actual rendered projection, including paused refits. Normal traffic uses the integer clock; an ending swept hit freezes poses at its fractional contact time without changing the integer clock contract for live play.

Core order is input -2 → clock -1 → game-time -0.75 → simulation -0.5 → camera -0.25 → visuals 0. No first-child Simulation or mount-order dependence. `useFrame` visuals use `useGameTime().now`/`.delta` for decorative easing and `.play` for play-relative clips; hop/squash read the simulated phase and cannot decide collisions or landing times. No `setTimeout`, `performance.now`, `Date.now`, tween completion callbacks or stored `state.clock.elapsedTime`. Pause freezes both gameplay and `useGameTime`; paused resize/refit never advances traffic. Pure clock tests use `advanceRunClock` and `playedFrameDt` with the real store.

**After the run: the core's 800 ms result delay.** The definition sets no `resultDelayMs`. `useRunFrame` stops during `"over"`, and CameraRig's damping becomes 0, retaining its lens and frozen position. A loss starts a visual-only 250 ms flatten with `useGameTime().now`: y scale 1 → 0.3, the frozen hop height lowers to the floor, and x scale stays 1. This does not change the simulation's contact or move traffic. `camera.test.ts` pins ground contact after a mid-air hit. Timeup holds the last pose without animation. Core submits score/duration before the delay, then shows Retry/Exit after 800 ms.

## Scoring

| Event | Points |
|---|---|
| First surviving landing on each new furthest row of the level | +10 |
| Far-side landing completes the 20-row level | +100 bonus, in addition to the final +10 |
| Revisiting / lateral / waiting / hit | 0 |

With completed levels k and current furthest row r in 0..19, raw score is **`300*k + 10*r`**. At the final landing normalize r = 0 and increment k in the same step. Highest-progress score does not decrease on retreat. Default final score/duration comes from store score / `Math.round(elapsedMs)`; GameShell submits. `end("lose")` is still ranked for this points game. Exit uses shell quit and does not submit.

### Server limits and why they hold (the proof)

Unchanged `meta.scoring` / WP limits: points, **50000** maximum, base **0**, **100 pts/s**, **3000–1800000 ms**, `pts`, integer display. We prove the raw score is already valid for **any play**, not merely a shortest successful route.

1. Let h be completed hops (including lateral/backward/repeated ones), and let **n = 20*k + r** be credited forward rows. A single hop advances at most one row and only landing awards progress, so h >= n. Every hop consumes >=0.55 s, whatever started it (a key, a swipe, a tap or the queue); the initial preview consumes 3.05 s. Pauses, waits, backtracking and queue gaps only add time. Thus simulation time s >= `3.05 + 0.55*n` whenever progress is awarded.
2. Core RunClock counts `frameMs` before default-priority simulation, including countdown-transition residual play. The carried integer-ms clock never leads it, so submitted time satisfies the stronger **`t >= 3.05 + 0.55*n`**. Retain **50 ms as conservative slack only**, giving the weaker bound **`t >= 3.00 + 0.55*n`** used below; no frame is untimed. Duration rounding does not weaken the integer-ms thresholds. A collision is enabled only after the protected preview, so every submitted loss is >=3000 ms; the shell cap clamps duration at exactly 1800000 ms. The result delay comes after the run's end and adds neither time nor points.
3. Raw score S = `300*k + 10*r`. At the earliest permitted duration the rate cap is `100*t >= 300 + 55*n = 300 + 1100*k + 55*r`. Its margin over S is **`300 + 800*k + 45*r`**, always nonnegative. For n = 0, S = 0 even during preview; for the first credited row S = 10 at t >=3.55 s, giving cap 355 and margin 345. A completed first level has S = 300 at t >=14 s, cap 1400. Collision before a landing grants no extra points; bonuses never arrive before the 20th hop.
4. For all ranked runs t <=1800 s, the conservative slack gives n <= `floor((1800 + 0.05 - 3.05)/0.55) = 3267` (the stronger current-clock bound yields the same integer). Score is increasing in n, with k = 163 and r = 7 at that bound: **48970 pts**, below 50000 by **1030**. Real traffic and waits can only lower it. The final clock-timed-out frame may skip simulation, which cannot increase this bound.
5. Earliest possible 50000: after 166 full levels and 19 rows the score is 49990; completing level 167 would jump to 50100. That requires **3340** credited hops and t >= `3 + 0.55*3340 = 1840 s`, **40 s after the 1800 s cap**. Hence no reachable run can hit/exceed 50000 before maxDurationMs. Neither a fast seeded gap sequence nor queued inputs can break this bound.

Reachable scores already fit. Use **core `capScore(rawScore, elapsedMs, meta.scoring)` and `withinServerLimits`**, not a local formula/helper; tests prove the cap is a **no-op** on every reachable ranked loss/time-out. Score/stat events update the store before end, so default shell score/duration suffices, including shell time-up; no `definition.finalScore` override is needed. Do not run the minimum-duration assertion on an unsubmitted preview prefix. At a cap/collision tie, core RunClock ends with timeup first, so the last frame cannot award points or overwrite the reason. No numeric metadata changes are needed: the camera, input and result-delay changes in this revision touch none of the proof's terms.

## Scene and camera

Three-quarter view looking forward along -z, **55° pitch**, yaw 0, vertical FOV **45°** (`definition.camera.fov: 45`, so `useFittedView` reads it from the canvas camera), near 0.1 / far 400. Forward stays forward on screen; never turn yaw 90°. Camera fitting comes from **core `useFittedView` / `fitView`**, placement/follow/lens shift from **`CameraRig`**, and UI rectangles from **`useSafeArea`** (read by `useFittedView`). `camera.ts` holds only street constants, the lane horizon and the view gate; it does not implement a binary-search fitter, lens-shift utility or DOM observer. First-frame camera (`index.tsx`): the 375 × 812 fit, `position: [0, 29.711, 17.204]`, `lookAt: [0, 0, -3.6]`; the Scene's rig takes over on mount.

Use a translation-invariant view in coordinates relative to the pigeon: `area = { min: { x: -5.6, y: 0, z: -11.1 }, max: { x: 5.6, y: 1.8, z: 3.9 } }`, `focus: [{ x: 0, y: 0, z: -3.6 }]`, `pitch: 55° in radians`, `yaws: [0]`, `margin: { top: 0.11, bottom: 0.09, left: 0.02, right: 0.02 }`, `padding: 8`, `shift: true`. Keep these objects at module scope. The six-ahead/two-behind active box is z = -10.8…3.6; the fitted box adds **0.30 m camera-lag guards** and the 1.8 m height envelope (vehicles ≤1.5 m, the hopping bird ≤1.5 m). Neither box is a generation/culling boundary. The x extent is the playable width itself and the side margins are 2 %: portrait fits are bound by the width, and this grows the bird by about 7 % over the earlier ±5.8 m / 4 % box (25.88 → 27.68 px at 375 × 812, 24.18 → 25.82 px at 360 × 640). The blocks' inner faces at |x| = 6.0 stay on screen from two rows behind (visible ground half-width 6.15 m at 375 × 812) to the far rows (6.54 m at the pigeon's row), so vehicles visibly emerge from cover in every row the player reads.

After simulation, update the existing follow point to `(0, 0, pigeon.z - 3.6)`. Pass it to `CameraRig follow`, with `followFraction={1}`, `offset={view.offset}`, `shift={view.shift}`, `damping={12}` and matching FOV/look-at configuration. Keep x = 0 and y = 0; follow only longitudinal progress, including mid-hop interpolation. At maximum z speed `1.8 / 0.55 = 3.273 m/s`, steady following lag is bounded by `speed / 12 < 0.273 m`, inside the 0.30 m guards. The fit is translation-invariant, so the canonical focus represents every settled scrolling position; do not try to fit the whole endless route or a finite world origin. No independent camera motion using wall/visual time. CameraRig's core priority places it after simulation and before visuals. The lens shift survives Retry remounts (core); the Scene needs no lens workaround.

**Safe area.** `useFittedView` consumes the live `useSafeArea` HUD/control/obstruction rectangles and refits on size/banner changes. It reads the whole safe area, which changes whenever a HUD chip changes width (the Score chip grows with the score), so `useFittedView`, `CameraRig` and the view gate live in one small `<StreetCamera>` component: a chip change re-renders only it, never the Scene with its pools. Any other safe-area read in the Scene uses the **selector form**, `useSafeArea((area) => …)` (with `sameScreenRects` for rect lists), never the full `useSafeArea()`. `definition.Hud` is rendered outside the shell's `SafeAreaProvider` (`useSafeArea` returns an empty layout there), so the Hud positions itself with CSS: the preview label and gate hint sit at the bottom, above `var(--arcade-bottom-obstruction)` (the cookie banner), `pointer-events: none`, CSS Modules and existing vars. They are **not** marked `data-arcade-safe-area`: a marked 56 px strip would shrink every height-bound fit for a label shown 3 s (812 × 375 bird 22.34 → 20.15 px, 1280 × 800 with the banner 46.29 → 42.23 px). Swipe/tap has no joystick/Jump/Action buttons, so `controls` is empty. The core owns rectangle measurement and lens shift. During eased refits retain the union of the previous, target and actual rendered-camera horizons/side cover until settled. A generic CameraRig/refit defect belongs to Claude, not a local replacement rig/fitter.

**Street horizon:** intersect rays through all four **full canvas** corners with y = 0 and y = 1.8, using reusable Three.js rays/planes/vectors. The envelope includes lanes behind the translucent HUD. Cache its extrema relative to camera z; ordinary follow uses that one actual projection plus scalar camera translation. ## Edge cases

- Pause mid-hop freezes interpolation, queued direction and all cars/gap clocks. Resume continues that hop, with no jump from reset R3F elapsed time. A press made while paused is cleared by the phase change and never hops. Frozen resize just fits the camera.
- Hop into a car, or car crosses between frames: the swept hit ends lose at the contact instant; no landing award/bonus afterward. Air height does not make the bird immune. A queued move cannot rescue a dead pigeon.
- One swipe is one hop: it arrives as `pressed`, and the game has no `swipe` branch, so it never also queues a second hop. A key pressed and released between two frames still hops once. A tap hops forward on release; a swipe gesture never also taps.
- During the 800 ms result delay nothing simulates: traffic, the hop and the camera hold, the car that hit stays touching the flattening bird, and no score/stat changes land. Timeup holds still with no animation.
- Initial preview ignores movement events, including a held key; it is playing time, unlike countdown. Idle start-grass run remains safe, scores 0 and reaches the 30-minute cap with timeup.
- Far-side grass cannot be hit; collision still precedes awards. Increment level/bonus exactly once, discard queue and preserve global time/physical boundary. Backtracking cannot replay completed levels or farm furthest-row points.
- An invalid queued request is dropped using the current hop's destination cell and leaves the slot empty; a later valid request can queue. A valid queued request is still discarded on death or far-side activation.
- A traffic cycle wrap deactivates/activates only under full side cover; never sweep a modulo teleport through the pigeon. Lane reuse occurs outside the camera-derived visible envelope, not merely outside the active box. The next level's already-visible traffic keeps its phase when activated.
- A hit before 3000 ms is impossible because preview locks the pigeon on protected grass. At the 30-minute collision tie, shell timeup has priority. Quit saves nothing; ranked losses/timeups retain earned points.
- Restart remounts Scene with fresh seed, state, weights/descriptors and queue. Strict Mode may initialize twice, with no shared mutable run data or paid effects. Cap/difficulty do not leak from the last run.
- Scene initializes the Level stat to 1 once per mount, including Retry, before playing; idle/paused frames do not rewrite it. Landscape on a coarse pointer shows the shell's rotate overlay; a failing fine-pointer view pauses through the gate; refit/prefill at frozen time before Resume, preserving queue, traffic and pool identities.
